## 4. Infra (fleet repo — cross-repo, tracked here for plan completeness)

- [x] 4.1 Added `rampme-backend-refresh-accessibility` `CronJob` (weekly, Monday 03:00) to `fleet/apps/rampme/backend/overlays/production/cronjob.yaml`. **Superseded the original `PersistentVolume` plan**: the backend's existing `rampme-backend-data` PVC is `ReadWriteOnce`, and per the fleet wiki two pods must never hold it at once — a periodic Job co-mounting it alongside the always-running Deployment pod would violate that. Delivers via `ConfigMap` instead (no such constraint, and the ~20KB dataset fits comfortably under its 1MiB limit): an `initContainer` runs the backend image's `./refresh-accessibility` binary into a scratch `emptyDir`, a `kubectl` container applies it as a `ConfigMap`, scoped via a dedicated `ServiceAccount`/`Role`/`RoleBinding` (`cronjob-rbac.yaml`) to exactly that one object. Verified by rendering the full overlay with `kubectl kustomize` — resources compose cleanly, RBAC scoped correctly, `$imagepolicy` marker present so Flux keeps the `CronJob`'s image in sync with the Deployment's. **Not yet verified against the live cluster** (no access from this session) — flagged the `kubectl` image's version tag as a guess needing the fleet maintainer's confirmation.
- [x] 4.2 Patched the backend `Deployment` (`deployment-patch.yaml`) with a second, `optional: true` volume mounting the `ConfigMap` at a path distinct from the `ramp.db` PVC, plus a `RAMP_ACCESSIBILITY_DATA_PATH` env var override pointing there. `optional: true` matters concretely: the `ConfigMap` doesn't exist until the `CronJob`'s first run, and without it the pod would sit in `ContainerCreating` forever.
