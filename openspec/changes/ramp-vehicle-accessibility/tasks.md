## 4. Delivery (GitHub Actions + fleet)

No in-cluster CronJob or RBAC — the refresh runs as a scheduled GitHub Actions workflow and commits its output directly into `fleet`, exactly like image-tag automation already does (see design.md Decisions).

- [x] 4.1 Added `.github/workflows/refresh-accessibility.yaml`: weekly schedule + `workflow_dispatch`, runs `scripts/refresh-accessibility.ts`, generates a `ConfigMap` manifest (`kubectl create configmap --dry-run=client`, no live cluster access needed), commits it into a checked-out `fleet` repo using a `FLEET_REPO_TOKEN` secret (PAT scoped to `fleet`'s `contents: write` only), pushes only if the content changed.
- [x] 4.2 Added `fleet/apps/rampme/backend/accessibility-refresh/` as a third sibling next to `base/` and `overlays/{production,stage}/` (not nested under either — both overlays already merge `base/` into one `apps/` Kustomization, so a resource under `base/` or duplicated per-overlay would register twice and fail the build). Contains just `configmap.yaml` (checked in with the current dataset) + `kustomization.yaml`. Registered once in `apps/rampme/kustomization.yaml`, sibling to both overlay paths.
- [x] 4.3 Moved the `ConfigMap` volume/mount/env var from a production-only patch into `fleet/apps/rampme/backend/base/deployment.yaml`, so production and stage share exactly one `ConfigMap` (fixed one landmine along the way: `overlays/stage/deployment-patch.yaml` is a JSON6902 patch whose `env` op *replaces* the whole array rather than merging, so `RAMP_ACCESSIBILITY_DATA_PATH` had to be added there explicitly too, not just in base). Verified: `kubectl kustomize` on the full `apps/` tree renders every resource exactly once, both `rampme-backend` and `rampme-backend-stage` Deployments reference the same `ConfigMap` name.
